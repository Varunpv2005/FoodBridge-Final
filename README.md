# FoodBridge

<p align="center">

**FoodBridge** is a real-time intelligent food redistribution platform that connects food donors, NGOs, and volunteers through AI-assisted matching, food-risk estimation, demand forecasting, route-aware logistics, and real-time delivery tracking.

# 1. Project Overview

FoodBridge is an intelligent, real-time platform designed to reduce surplus food wastage by efficiently connecting food donors with suitable NGOs and volunteers.

The platform integrates:

- Artificial Intelligence
- Machine Learning
- Food-risk estimation
- Demand forecasting
- Intelligent NGO matching
- Volunteer allocation
- Geospatial routing
- Expiry-aware logistics
- Real-time GPS tracking
- Route deviation detection
- WebSocket communication
- Conversational AI assistance

The complete redistribution process is coordinated through a centralized backend.

FoodBridge treats food redistribution as a time-sensitive logistics problem rather than simply a static donation listing system.

2. Problem Statement

A significant amount of surplus food is generated by:

Restaurants
Hotels
Events
Educational institutions
Catering services
Households
Corporate organizations
Other food providers

However, the availability of surplus food does not necessarily mean that it can be redistributed efficiently.

Traditional food donation workflows may depend heavily on:

Phone calls
Manual coordination
Static recipient lists
Manual volunteer assignment
Basic location matching
Delayed communication
Limited delivery visibility

These limitations can result in:

Food wastage
Delayed pickup
Increased spoilage risk
Poor donor-NGO matching
Inefficient volunteer utilization
Longer delivery times
Lack of real-time visibility

FoodBridge addresses these problems through an integrated intelligent and real-time system.

3. Motivation

The motivation behind FoodBridge is to bridge the gap between:

Food Surplus
      +
Organizations in Need
      +
Available Volunteers

The system aims to ensure that suitable surplus food reaches suitable recipients before the food's available safe consumption window becomes a limiting factor.

The platform focuses on three major areas:

Intelligent Decision Making

Use AI/ML and multi-factor evaluation to support matching and forecasting.

Real-Time Coordination

Keep donors, NGOs, volunteers, and administrators synchronized.

Logistics Optimization

Use geographic and route information to improve delivery feasibility.

15. NGO Request and Fallback Workflow

An important design decision is that the nearest NGO is recommended/requested, not automatically allocated.

The NGO must verify the donation before accepting it.

If the NGO rejects:

NGO 1
  |
  X Reject
  |
  v
NGO 2
  |
  X Reject
  |
  v
NGO 3
  |
  v
Accept

The next suitable NGO can then receive the request.

This prevents the system from treating geographic proximity as the sole measure of suitability.

If the safe window is short, the system can consider another suitable and feasible NGO rather than simply waiting indefinitely for an unsuitable recipient.

20. Arrival and Delivery Completion

Arrival is based on the latest persisted GPS position.

Arrival detection does not automatically complete the delivery.

   v

Single active session per account
Session rotation

Authorized WebSocket access
Authorized GPS updates
Single Active Session

Each account is designed to have one active session.

If the same account logs in again:

Old Session
     |
     v
Invalidated

New Session
     |
     v
Active

This prevents multiple simultaneous sessions for the same account.

30. Multi-Device Synchronization

Different role accounts can operate simultaneously on different devices and networks.

For example:

Laptop 1 → Donor
Laptop 2 → NGO
Mobile   → Volunteer
Laptop 3 → Admin

These devices do not need to share the same:

Wi-Fi
IP address
Network
Physical device

The backend synchronizes the state.

WebSocket events notify connected clients.

When a client reconnects, the frontend retrieves the authoritative current state from the backend.

This prevents the application from relying solely on previously received events.

41. Research Contributions

FoodBridge integrates several research and engineering components.

Contribution 1 — Hybrid Demand Forecasting

A hybrid XGBoost-LSTM approach is used for demand forecasting.

Contribution 2 — Multi-Criteria Matching

NGO matching considers multiple factors instead of relying only on geographical distance.

Contribution 3 — Expiry-Aware Logistics

The system considers safe-window constraints when evaluating redistribution feasibility.

Contribution 4 — Food-Risk Estimation

Food information is used to produce software-based risk estimates.

Contribution 5 — Real-Time Redistribution

WebSockets and browser GPS provide real-time delivery visibility.

Contribution 6 — Automated Volunteer Allocation

Volunteer assignment occurs after NGO acceptance using eligibility and route-aware ranking.

Contribution 7 — Conversational Assistance

The FoodBridge Assistant provides an AI-powered interaction layer.
